# 2. Техническое задание

## 2.1 Введение

**Наименование:** «Адал», платформа честного тестирования студентов (вариант 9 пособия: «Платформа тестирования студентов с таймером»).
**Цель:** проведение честного компьютерного тестирования с единообразным отображением
вопросов и формул, контролем добросовестности и анализом качества вопросов.
**Область применения:** контрольные мероприятия (модули, рубежные контроли, вступительные
тесты) в компьютерных аудиториях университета.

**Термины.** *Банк вопросов* — множество вопросов дисциплины. *Тест* — правила формирования
варианта (дисциплина, тема, число вопросов, время, группы). *Вариант* — набор вопросов и
порядок ответов, сгенерированный для конкретного студента. *Попытка* — прохождение варианта.
*Нарушение* — зафиксированное действие студента, похожее на списывание.

## 2.2 Пользователи и роли

| Роль | Права |
|---|---|
| Студент / абитуриент | Регистрация, вход, прохождение назначенных тестов, просмотр своих результатов |
| Преподаватель | Всё по банку вопросов; создание и настройка своих тестов; наблюдение, результаты, анализ, экспорт; управление попытками своих тестов |
| Администратор | Права преподавателя + панель администрирования (пользователи, роли) |

## 2.5 Ограничения и допущения

* Python 3.11+, Django 6, SQLite (для учебного проекта); для продакшена — PostgreSQL.
* Браузер не может полностью запретить ИИ-помощников: платформа фиксирует уход с теста,
  а полная блокировка требует сетевых мер университета или киоск-браузера.
* Формулы отображаются библиотекой KaTeX, загружаемой с CDN; при работе без интернета её
  нужно разместить локально.
* Срок разработки — 8 недель (раздел 3 пособия).

## 2.6 Модель данных

Пользователь (ИИН, ФИО, роль, группа, анкета) → создаёт Вопросы (дисциплина, тема, текст,
рисунок, сложность) с Вариантами ответа. Тест ссылается на Дисциплину и задаёт правила.
Попытка = Тест × Студент (уникально), содержит Элементы попытки (вопрос, порядок вариантов,
выбранный вариант) и Нарушения. Подробная схема — в [архитектуре](03-architecture.md#33-схема-базы-данных).

## 2.7 Критерии приёмки

На защите должно работать: регистрация и вход по ИИН; импорт .docx с предупреждением о
выделенном ответе; создание теста; прохождение теста с таймером и фиксацией ухода со вкладки
(видно в «Наблюдении»); результат студента; анализ вопросов; поиск, фильтры и сортировка;
переключение языка; `pytest` проходит без ошибок.
