# 1. Анализ задачи и аналогов

## 1.1 Постановка проблемы

В Кызылординском университете имени Коркыт Ата контрольные (модули, рубежные контроли)
проводятся в системе Platonus в компьютерных аудиториях. На практике выявлены две группы проблем.

**Проблема качества тестовых материалов.** Многие преподаватели готовят тесты в Microsoft Word
и загружают файл в систему. Оформление из Word (жирный шрифт, цвет, курсив) переносится как
есть, и правильный вариант нередко оказывается выделенным — студенты угадывают ответ по
оформлению, а не по знаниям. Формулы по математике и физике вставляются картинками и
отображаются размыто, а иногда не читаются вовсе.

**Проблема академической честности.** Во время теста студент может открыть соседнюю вкладку
с ChatGPT или вызвать встроенного ИИ-помощника браузера (например, «Спросить Gemini» по правой
кнопке мыши в Chrome). Преподаватель в аудитории этого не видит, а система никак не фиксирует.

## 1.2 Пользователи и их цели

| Пользователь | Цель | Типичный сценарий |
|---|---|---|
| Студент | Честно пройти тест и сразу узнать результат | Ввести код доступа → пройти тест в полноэкранном режиме → увидеть балл и разбор |
| Абитуриент | Зарегистрироваться и сдать вступительный тест | Заполнить анкету (как в Platonus) → войти по ИИН |
| Преподаватель (в т. ч. старшего возраста) | Быстро перенести вопросы из Word, провести тест и понять, какие вопросы плохие | Загрузить .docx → создать тест → наблюдать в аудитории → открыть анализ вопросов |
| Администратор | Управлять пользователями и ролями | Создать учётную запись преподавателя в панели администрирования |

## 1.3 Три основных сценария

1. **Преподаватель готовит тест.** Загружает старый .docx в формате Platonus; платформа снимает
   оформление, переводит формулы Word в LaTeX и показывает предупреждения («в файле правильный
   ответ был выделен», «картинка слишком мелкая»). Затем создаёт тест: число вопросов, время,
   группы, код доступа.
2. **Студент проходит тест.** Вводит код, получает свой случайный вариант, отвечает в
   полноэкранном режиме. Уход со страницы фиксируется; после лимита нарушений тест завершается.
3. **Преподаватель анализирует результаты.** Смотрит распределение баллов, ищет и фильтрует
   студентов, открывает анализ вопросов: трудность, различающую способность, неработающие
   варианты.

## 1.4 Анализ аналогов

| Критерий | Platonus | Moodle Quiz | Google Forms (режим теста) | **Адал** |
|---|---|---|---|---|
| Банк вопросов, случайные варианты | Есть | Есть | Нет банка, перемешивание только порядка | Есть |
| Импорт из Word | Есть, но с сохранением оформления | Через плагины (GIFT/Aiken), не .docx | Нет | Есть, оформление снимается |
| Формулы | Картинками из Word | MathJax/TeX | Нет | LaTeX + авто-перевод формул Word |
| Фиксация ухода со страницы | Нет | Только с Safe Exam Browser | Только в Chromebook (locked mode) | Есть, видно в реальном времени |
| Анализ вопросов (трудность, дискриминация) | Ограниченный | Есть (отчёт статистики) | Нет | Есть, с понятными подсказками |
| Вход по ИИН | Есть | Нет | Нет (аккаунт Google) | Есть |
| Казахский интерфейс | Есть | Частично | Есть | Есть (казахский, русский, английский) |
| Стоимость | Лицензия вуза | Бесплатно, нужен сервер и администратор | Бесплатно | Бесплатно, один сервер |

**Вывод.** Ни один из аналогов не решает одновременно обе выявленные проблемы для
пользователей, не готовых осваивать сложные системы. Moodle ближе всего функционально, но
требует сопровождения и не работает с привычными преподавателям файлами .docx. «Адал»
сохраняет привычный формат Platonus и добавляет то, чего в нём нет: нормализацию
материалов и прозрачный контроль честности.
